# 踩坑记录

记录 MiniServe 实现过程中遇到的问题、产生原因和正确做法，便于后续复查。

## 1. Tensor 形状与内存布局

### 1.1 `split` 的参数不是块数

**问题**：容易把 `split(n)` 理解成“切成 n 块”。

**原因**：`split(n)` 中的 `n` 表示每块的长度；需要指定块数时，应使用 `chunk(n)`。

```python
q, k, v = qkv.split(C, dim=-1)  # 每块长度为 C
```

### 1.2 多头注意力不能直接调整成目标形状

**问题**：直接使用 `view(B, nh, T, hs)` 拆头时，可能不报错，但数据位置已经错误。

**正确做法**：先保留时间维度，再交换头维度和时间维度。

```python
q = q.view(B, T, nh, hs).transpose(1, 2)
```

变换后的形状为 `(B, nh, T, hs)`。

### 1.3 `.T` 不适合高维张量的指定维度转置

**问题**：对四维张量 `(B, nh, T, hs)` 使用 `.T`，会将所有维度倒序，得到 `(hs, T, nh, B)`。

**正确做法**：二维矩阵可以使用 `.T`；高维张量使用 `transpose(dim0, dim1)` 或 `permute(...)` 明确指定维度。

### 1.4 `transpose` 的结果需要重新赋值

**问题**：调用 `y.transpose(1, 2)` 后直接使用原来的 `y`，形状没有变化。

**原因**：不带下划线的操作通常会返回新张量，不会原地修改原张量。

```python
y = y.transpose(1, 2)
```

### 1.5 转置后直接使用 `view` 可能失败

**问题**：`transpose` 后张量的内存不再连续，调用 `view` 可能报错。

**正确做法**：先调用 `.contiguous()`，或者根据场景使用 `reshape`。

```python
y = y.transpose(1, 2).contiguous().view(B, T, C)
```

## 2. 因果注意力 Mask

### 2.1 `masked_fill` 修改的是条件为 `True` 的位置

因果 Mask 需要屏蔽未来位置。对于下三角矩阵 `mask`，未来位置对应 `mask == 0`：

```python
scores = scores.masked_fill(mask == 0, float("-inf"))
```

### 2.2 被屏蔽的位置应填充 `-inf`

**原因**：Softmax 中 `exp(-inf) = 0`，因此填充 `-inf` 才能让未来位置的注意力权重变为 0。填充 0 只表示 logits 为 0，并不能屏蔽这些位置。

### 2.3 Mask 必须与输入位于同一设备

**问题**：`torch.ones(T, T)` 默认在 CPU 上创建张量，而模型输入可能位于 GPU，混合使用会报设备不一致错误。

**正确做法**：创建 Mask 时继承输入设备。

```python
mask = torch.tril(torch.ones(T, T, device=x.device))
```

## 3. GPT-2 模块实现

### 3.1 GPT-2 使用 tanh 近似版 GELU

默认的精确版 GELU 与 GPT-2 使用的激活函数不同，会导致输出无法与 HuggingFace 对齐。

```python
x = F.gelu(x, approximate="tanh")
```

### 3.2 合并注意力头前需要恢复连续内存

多头输出先从 `(B, nh, T, hs)` 转置为 `(B, T, nh, hs)`，再合并为 `(B, T, C)`。转置后应先调用 `.contiguous()`，否则 `view` 可能失败。

## 4. HuggingFace 权重加载

### 4.1 `Conv1D` 和 `nn.Linear` 的权重布局不同

HuggingFace GPT-2 的部分层使用 `Conv1D`，权重形状为 `(in, out)`；PyTorch `nn.Linear` 的权重形状为 `(out, in)`。加载以下权重时需要转置：

- `attn.c_attn.weight`
- `attn.c_proj.weight`
- `mlp.c_fc.weight`
- `mlp.c_proj.weight`

仅比较形状无法发现所有转置错误，因为部分权重是方阵，转置前后形状相同。

### 4.2 加载参数时使用原地复制

加载权重需要保留模型原有的参数对象，并在不记录梯度的上下文中复制数据：

```python
with torch.no_grad():
    dst.weight.copy_(src.weight)
```

### 4.3 原地修改需要区分对象

- 加载模型参数时，可以使用 `copy_` 等原地操作更新目标参数。
- 处理调用方传入的输入张量时，不应随意原地修改，避免产生难以排查的副作用。

## 5. 数值对齐的排查顺序

当模型输出与 HuggingFace 不一致时，按由小到大的顺序排查：

1. 检查输入和输出的形状。
2. 对齐 Attention，并额外验证因果性。
3. 对齐 MLP，检查 GELU 类型。
4. 对齐 Block，检查 LayerNorm 和残差连接顺序。
5. 对齐完整模型，检查 Embedding、权重共享和参数量。
6. 逐参数检查权重名称、形状、数值及是否需要转置。
7. 最后比较 logits 和逐 token 生成结果。

这种方式可以把问题定位到具体模块，避免直接在完整模型中盲目调试。
